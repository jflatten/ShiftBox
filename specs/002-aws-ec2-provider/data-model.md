# Private ShiftBox on AWS data model

| Entity | Fields and relationships | Invariants |
| --- | --- | --- |
| AWS deployment | Account, region, Availability Zone, VPC, service and workspace subnets, private DNS namespace and controller task role. | One EC2-only installation and one approved AWS target. Terraform owns shared infrastructure and private service identities. |
| ECS persistent storage | Independently provisioned encrypted EBS volume ID, distinct PostgreSQL and ShiftBox host paths, task identity and mount readiness. | Both tasks require mounted expected state. Only the controller and setup share the installation path. The database owns its separate path. Host or task replacement retains the volume. |
| Installation | Existing installation ID, administrator identity, setup and activation state, PostgreSQL endpoints and scoped roles, TLS, keys and CA. | One active controller. A one-off setup task and the running controller use the same installation lock. Sensitive values belong to protected state or operator-handled secret inputs. |
| EC2 platform artifact | Existing release, platform, architecture, guest and protocol fields plus provider kind, region, AWS owner, AMI ID, source AMI publisher and ID, root snapshot identity and size, manifest digest, provenance and validation state. | Verify exact owner, account/region, HVM, x86-64, EBS root and a single expected disk mapping. The available artifact is immutable. A new release has a new catalog identity. Backfill existing catalog records as UTM. |
| AWS resource profile | Human-readable name, platform artifact reference, offered EC2 instance type, AWS-derived CPU and memory, independently selected EBS size, enabled state and version. | The profile owns the AMI used by future launches. Its instance architecture and EBS minimum must match the approved image. Templates need only the profile. Existing workspaces retain their pinned image and resources after profile edits. |
| Workspace launch binding | Existing workspace and template revision, artifact/provider kind, account, region, subnet, security group, instance type, exact allocation and networking policy. Existing installation ID, workspace ID, generation and ownership marker identify the logical workspace. | Pin before provisioning, retain through reboot and restore, and resolve the same adapter even without an instance ID. EC2 resource profile must match a supported x86-64 instance shape. Root disk is whole GiB and at least the image minimum. |
| Provider resource and operation evidence | Existing operation ID, stable EC2 client token, verified AWS instance ID, encrypted root volume ID, primary ENI ID, placement, expected ownership tags and last observed state. Mark shared artifacts and infrastructure as outside workspace ownership. | Record partial owned resources before final provision completion when observed. Do not adopt conflicting identities or erase evidence on timeout. Verify termination and cleanup of every recorded owned disk and ENI before marking deletion complete. |
| Enrollment delivery | Existing grant digest, target registration and workspace generation, verified instance and operation ID, expiry and delivery evidence. Store transport kind, payload digest and state needed to reconcile a write. | Only mint for a verified stopped and eligible instance under current authority. Keep raw seed out of ordinary journals, observations and API responses. Reconcile an ambiguous write by digest without logging payload. Invalidate expired or replaced grants and verify spent/revoked grants cannot enroll. |

## State transitions

- **Deployment** moves from infrastructure ready through protected setup and PostgreSQL activation to active controller. Workspace launches stay blocked until a platform canary succeeds. Missing mounted state prevents startup. An AWS permission failure retains existing provider bindings and inventory.
- **Image** moves from validating to available only after metadata, boot and cleanup checks succeed. Failed candidates stay unavailable.
- **Instance** moves from provisioning through EC2 pending, inert running and stopping to provisioned stopped. The authenticated workspace start is a separate journaled transition. Normal stop preserves storage. Delete completes after termination and owned-resource removal.
- **Enrollment** moves from eligible or expired through grant issuance, verified delivery and consumption to an active registration. Revoked and deleted registrations deny recovery. A late AWS response cannot revive a superseded generation or operation.
